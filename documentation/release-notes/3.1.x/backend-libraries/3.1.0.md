# NL-Portal Backend Libraries 3.1.0

## Nieuwe Functionaliteit

De volgende functionaliteiten zijn nieuw toegevoegd:

### Ondersteuning voor Keycloak Standard Token Exchange (v2)

De backend ondersteunt nu, naast de legacy token exchange (v1), ook de Standard Token Exchange van
Keycloak 26.2 en nieuwer. Je kiest per omgeving welke variant je gebruikt met de nieuwe property
`nl-portal.authentication.keycloak.token-exchange-version`, of met de environment variabele
`KEYCLOAK_TOKEN_EXCHANGE_VERSION`. De standaardwaarde is `v1`, dus bestaande omgevingen werken
zonder aanpassing verder.

Met v2 heeft de NL Portal de Keycloak feature `token-exchange:v1` niet meer nodig, en daarmee ook
`admin-fine-grained-authz:v1` niet. Daardoor komt Fine-Grained Admin Permissions v2 beschikbaar op
de Keycloak waarop de portal draait.

Zie [Standard token exchange (v2)](../../../configuratie/keycloak-token-exchange-v2.md) en
[Legacy token exchange (v1)](../../../configuratie/keycloak-token-exchange-v1.md).

### Overstappen naar v2

Vereist Keycloak 26.2 of nieuwer. Stap 1 tot en met 3 kun je toepassen terwijl de portal nog op v1
draait: de bestaande flow blijft dan werken.

1. Maak een client scope aan met de protocol mappers voor `aanvrager.bsn` en `aanvrager.kvk`, en
   koppel die als default scope aan de m2m client.
2. Voeg op de frontend client een audience mapper toe die de m2m client als audience meegeeft.
3. Zet op de m2m client de schakelaar Standard token exchange aan.
4. Pas de configuratie van de backend aan en deploy:

   ```yaml
   nl-portal:
       authentication:
           keycloak:
               token-exchange-version: v2
   ```

   of met de environment variabele van de app image:

   ```
   KEYCLOAK_TOKEN_EXCHANGE_VERSION=v2
   ```

   Haal `KEYCLOAK_TOKEN_EXCHANGE_AUDIENCE` weg, of maak hem leeg. De oude waarde (de doelclient) is
   in v2 ongeldig: Keycloak antwoordt dan `Requested audience not available`. Zonder waarde bepaalt
   de m2m client zelf de claims, wat is wat je in deze opzet wil. Vul je hem toch, dan moet het een
   audience zijn die de m2m client al kan afgeven.

5. Controleer of inloggen werkt. Terugdraaien kan door de property weer op `v1` te zetten; de
   Keycloak configuratie van stap 1 tot 3 hoeft daarvoor niet terug.
6. Ruim daarna op: verwijder de token exchange permission op de doelclient, verwijder de doelclient
   zelf, en haal `token-exchange:v1` en `admin-fine-grained-authz:v1` uit `KC_FEATURES`.

Let op bij het controleren in stap 5: dat inloggen blijft werken bewijst niet dat je op v2 zit. Zet
je alleen de property om zonder stap 1 tot 3, dan handelt de legacy engine het verzoek gewoon af en
merk je niets. De controle die wel iets zegt is de schakelaar Standard token exchange op de m2m
client in Keycloak.

### Audience validatie mogelijk gemaakt

De backend controleert standaard alleen de handtekening en de geldigheidsduur van een token, en accepteert daarmee elke token die door hetzelfde realm is ondertekend, ongeacht voor welke client die is uitgegeven. Met de v2 opzet kun je dat aanscherpen: geef zowel de frontend client als de m2m client een audience mapper die de m2m client als audience meegeeft, en zet vervolgens
`SPRING_SECURITY_OAUTH2_RESOURCESERVER_JWT_AUDIENCES` op de client id van de m2m client. Tokens van andere clients in het realm worden dan geweigerd.

Dit is optioneel en staat standaard uit, ook in de Helm charts, omdat het alleen werkt wanneer de Keycloak configuratie erbij past. Zie
[Audience validatie](../../../configuratie/keycloak-token-exchange-v2.md#audience-validatie-aanbevolen).

### Helm chart 3.2.0

De `nl-portal-backend` chart 3.2.0 sluit hierop aan met drie wijzigingen: de nieuwe waarde
`settings.keycloak.tokenExchangeVersion` (standaard `v1`), `settings.keycloak.audience` die alleen
nog verplicht is bij `v1`, en de optionele `settings.keycloak.acceptedAudiences`. De chart weigert
`v2` te renderen wanneer de gedeployde versie ouder is dan 3.1.0.

## Bugfixes

De volgende bugs zijn opgelost:

* Wanneer Keycloak een token exchange weigert, wordt de foutmelding van Keycloak nu gelogd, samen met
  de actieve variant. Voorheen verdween die tekst en bleef alleen een HTTP status over.

## Breaking changes

`KeycloakConfig` heeft een extra constructor parameter gekregen en `audience` is nullable geworden
(`String?`, standaard `null`). Dit raakt alleen code die deze klasse zelf instantieert of de property
uitleest; configuratie via `application.yml` of environment variabelen verandert niet. Gebruik je de
klasse programmatisch, dan is hercompileren tegen 3.1.0 voldoende:

```kotlin
KeycloakConfig(
    resource = "nl-portal-m2m",
    audience = null,
    credentials = KeycloakConfig.KeycloakCredentials("..."),
    tokenExchangeVersion = KeycloakConfig.TokenExchangeVersion.V2,
)
```

De environment variabele `KEYCLOAK_TOKEN_EXCHANGE_AUDIENCE` is niet meer verplicht voor de app image.
Bij v1 blijft hij nodig; ontbreekt hij, dan meldt de applicatie dat bij het opstarten en faalt de
eerste token exchange met een melding die de property benoemt.

## Deprecations

De legacy token exchange (v1) blijft in 3.x de standaard, maar is door Keycloak als deprecated
gemarkeerd en wordt in een toekomstige Keycloak versie verwijderd. Keycloak voegt geen ondersteuning
voor token exchange permissions toe aan Fine-Grained Admin Permissions v2, dus v1 blijft FGAP v1
vereisen.

De property `token-exchange-version` is nieuw in 3.1.0. In 4.x kan deze een andere naam krijgen of
de standaardwaarde `v2` worden.
