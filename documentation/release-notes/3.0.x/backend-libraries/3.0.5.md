# NL-Portal Backend Libraries 3.0.5

## Nieuwe Functionaliteit

De volgende functionaliteiten zijn nieuw toegevoegd:

* Nieuwe configuratie-eigenschap `nl-portal.config.product.verbruiks-object-modification-enabled`
  (standaard `false`). Hiermee kan het wijzigen van verbruiksobjecten via de GraphQL-mutatie
  `updateProductVerbruiksObject` weer worden ingeschakeld. De eigenschap werkt alleen in combinatie
  met `nl-portal.config.product.enabled: true`. Dit is geen nieuwe functionaliteit om te gaan
  gebruiken, maar een onveilige terugvaloptie voor bestaande implementaties. Zie "Breaking changes"
  en "Deprecations".

## Bugfixes

De volgende bugs zijn opgelost:

* De applicatiebeveiliging is op meerdere punten verbeterd.

## Breaking changes

* **Het wijzigen van verbruiksobjecten is standaard uitgeschakeld.** Deze wijziging is om
  veiligheidsredenen doorgevoerd. Aanroepen van de GraphQL-mutatie `updateProductVerbruiksObject`
  leveren vanaf 3.0.5 een fout op.

  De frontend-API blijft ongewijzigd: de hook `useUpdateProductVerbruiksObjectMutation` uit
  `@nl-portal/nl-portal-api` blijft bestaan en blijft compileren, maar de aanroep faalt aan de
  serverzijde.

  **De nieuwe configuratie-eigenschap is een onveilige terugvaloptie en geen aanbevolen
  configuratie.** Inschakelen maakt de applicatie minder veilig. Schakel de eigenschap uitsluitend in
  wanneer dat strikt noodzakelijk is om een bestaande implementatie werkend te houden, uitsluitend
  tijdelijk, en alleen na een eigen risicoafweging.

  ```yaml
  nl-portal:
      config:
          product:
              enabled: true
              verbruiks-object-modification-enabled: true
  ```

  De aanbevolen route is niet inschakelen en migreren naar de `openproduct`-module. Zie
  "Deprecations".

## Deprecations

* De GraphQL-mutatie `updateProductVerbruiksObject` is gedeprecieerd en wordt verwijderd in 4.0.0.
* De configuratie-eigenschap `nl-portal.config.product.verbruiks-object-modification-enabled` is
  direct bij introductie gedeprecieerd en wordt samen met de mutatie verwijderd in 4.0.0. De
  eigenschap bestaat uitsluitend om bestaande implementaties tijd te geven om te migreren.
* Implementaties die verbruiksobjecten moeten kunnen wijzigen, dienen over te stappen op de
  `openproduct`-module en de mutatie `updateProduct`.

## Bekende problemen

Er zijn geen bekende problemen.
